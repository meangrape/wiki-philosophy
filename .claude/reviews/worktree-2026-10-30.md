## Audit Report — wiki-philosophy, whole repository (working tree vs empty tree, excluding generated philosophy.txt/md/pdf and Cargo.lock; 17 files, 1912 lines)

### Priority Findings (correctness > performance > resources)

1. [CORRECTNESS] [UNVERIFIED] src/main.rs:113-116 (rust-1, major). `is_namespaced` lowercases the prefix (`p = prefix.trim().to_ascii_lowercase()`) and then tests `p.bytes().all(|c| c.is_ascii_lowercase() || c == b'-')`. After lowercasing, that test is always true, so every 2-12 letter "Word:" prefix counts as a namespace. Real article links like [[Dune: Part Two]], [[Halo: Reach]] and [[Alien: Covenant]] get skipped (line 203), and `<redirect title=...>` targets with such titles are dropped (line 305). Those redirects then look like dead ends, which feeds into finding 7. This also contradicts the function's own doc comment (lines 101-103). Fix: check the case of the original, un-lowercased prefix, or match against the real interwiki/language code list. The source alone settles the bug. It is UNVERIFIED only because `cargo test` was held, so the number of affected titles is unknown.
2. [CORRECTNESS] tools/psql_to_md.py:74 (python-1, major). The stage regex `(?:\s+(strict|paren))?` only accepts the old rule names. For parens_ok, skip_parens, skip_italics and loose, 8 of the 12 H2 headings in the PDF and its TOC come out as raw marker text with timestamps (philosophy.md:426, 553, 664, 776, 1073, 1294, 1469, 1689). Because stage_rule stays None, those sections also get duplicate `### Rule:` headings. Fix it together with finding 9: widening the regex alone exposes a KeyError on `RULES[rule]` at line 85.
3. [CORRECTNESS] [UNVERIFIED] Makefile:105-108 (devops-2, major). `make docs` touches only the load and topology stamps, then runs `$(MAKE) pdf`. The sub-make still walks articles -> topology -> load -> $(CSV) -> $(BIN)/$(DUMP). So any edit to src/main.rs or Cargo.toml reruns the multi-hour parse, and the 01_load DROP-and-reload after it. A missing or renamed dump (the dated default at line 23) makes docs, all, report, stats and compare fail with "No rule to make target". Today's mtimes are in order, so it does not fire right now. It is UNVERIFIED because `make -n -W` was banned, but it follows deterministically from GNU make semantics. Fix: give docs a target with no stamp prerequisites, or make $(DUMP) order-only or guard it with $(wildcard).
4. [CORRECTNESS] Makefile (whole file) plus src/main.rs:417 (devops-1, major). There is no `.DELETE_ON_ERROR:`, and the parser writes straight to the final OUTPUT_CSV path. If the parse fails partway, through an I/O or XML error via `?` or through a panic (.cargo/config.toml sets panic = "abort" for release, which the second pass confirmed), a truncated wiki_edges.csv is left with a fresh mtime. The next `make` then COPYs it as current. philosophy.txt (`{ ...; } > $@`, lines 88-94) has the same problem. Fix: add `.DELETE_ON_ERROR:`, or write to `$@.tmp` and `mv` it into place.
5. [CORRECTNESS] Makefile:25 (devops-3). PSQL is `psql -X -d $(DB)` with no `-v ON_ERROR_STOP=1`, and 03_report, 04_compare, 05_stats, 06_summary, 06_summary_rule and rule_vars do not set it. A SQL error in report or stats exits 0, its ERROR text lands in philosophy.txt via `2>&1`, and from there it goes into the PDF. This also makes finding 14 worse. Fix: add `-v ON_ERROR_STOP=1` to PSQL.
6. [CORRECTNESS] README.md:255-256 (general-purpose-2). The README says "Under every other rule Philosophy returns to itself in 9 clicks." The generated output disagrees. Under skip_parens it never returns (Philosophy -> Existence -> Reality, philosophy.txt:112). Under skip_italics it takes 16 clicks (line 1583). Only parens_ok and loose match the README.
7. [CORRECTNESS] sql/01_load.sql:81-103 with sql/02_topology.sql:37 and sql/03_report.sql:51,60 (general-purpose-5). When an article's first link goes to a redirect that never resolves (a loop, more than 10 hops, or a namespaced target dropped at main.rs:304-306), `next_<rule>` becomes NULL. The article then becomes its own distance-0 sink and is classified as kind 'none' ("page has no qualifying first link"), when the dead end belongs to the redirect. Finding 1 adds more redirects to this group. One evidence detail was off: README line 50 is not the definition of the kinds. That does not change the verdict.
8. [CORRECTNESS] src/main.rs:195-199 (rust-4). The target scan stops at `|`, `]`, `[` or `\n` and never checks what it stopped on. So `[[Foo\n`, `[[Foo]` and `[[Foo[[Bar]]` all record "Foo" as the first link. Fix: require `|` or `]]` immediately after the target. Same-line caption termination should not be required, because captions can span lines.
9. [CORRECTNESS] tools/psql_to_md.py:14 (python-2). The RULES dict is stale. strict is described as "parenthesized links are skipped", but rule_vars.sql:14 says parenthesized, italicized and template links are skipped (philosophy.md:52, 301, 903). It still has a dead 'paren' key and no descriptions for the four current non-strict rules (md:78, 102, 126, 150). The unguarded `RULES[rule]` lookup will raise KeyError once finding 2 is fixed.
10. [CORRECTNESS] src/main.rs:99 (rust-2). When a skip-tag that is not self-closed (<ref>, <nowiki>, <math>, ...) has no closing tag, `markup_skip_len` returns `Some(s.len())`, which discards every later link on the page. That can create false dead ends or pick the wrong first link. MediaWiki lets a missing end tag run to the end of text only for includeonly, noinclude and onlyinclude. For any other tag, the unclosed opener is treated as literal text. The code comment says the behavior is deliberate, but it is semantically wrong. Fix: return None, or `Some(gt + 1)`. Line 74 (an unterminated comment runs to the end) is correct.
11. [CORRECTNESS] src/main.rs:355-358, 457-459 (rust-6). After a quick-xml error, process_xml breaks and silently drops the rest of the batch. After a bzip2 error, a truncated buffer is parsed anyway. The "Done" summary has no failed-batch or skipped-page count, and main returns Ok, so exit code 0. Downstream, the missing pages turn into unresolved targets. Fix: count errors in the summary and/or exit non-zero.
12. [CORRECTNESS] tools/psql_to_md.py:15 (python-3). STAGES labels the compare section "Strict rule versus parentheses rule" (philosophy.md:174). 04_compare.sql actually compares all five rules against strict.
13. [CORRECTNESS] [UNVERIFIED] Makefile:53-57 with sql/02_topology.sql:58 (devops-4). Nothing serializes the topology-% stamps, so under `make -j` five psql sessions each run an unqualified `CREATE OR REPLACE FUNCTION strip_leaves` on the same pg_proc row at the same time. That can raise "tuple concurrently updated" or a pg_proc unique-index error, and with ON_ERROR_STOP on, a random rule fails. The race was not reproduced because psql was not allowed. Fix: create the function once in 01_load.sql, or add `.NOTPARALLEL`.
14. [CORRECTNESS] sql/05_stats.sql:67 (general-purpose-6, downgraded in scope). When no distance has 10 or more reaching articles, `max(distance)` returns NULL. `\gset` then leaves :crowded_max unset, and the queries at lines 70, 78 and about 90 fail with syntax errors. ON_ERROR_STOP is off, so only those three queries are lost, not the rest of the script as the finding claimed. Because of finding 5, their errors end up in the report silently. Fix: `coalesce(max(distance), -1)`.
15. [CORRECTNESS] sql/06_summary_rule.sql:15 (general-purpose-4). The label "(loops without Philosophy)" is applied whenever `bool_or(next_id = :philosophy_id)` is false. That includes a dead end (next_id NULL or no matching row) and a chain cut off at pos < 50, so both would be mislabelled as loops. Latent on the current dump.
16. [CORRECTNESS] sql/04_compare.sql:83-94 (general-purpose-1). The 0..35 spine is `d LEFT JOIN c USING (dist)` and is never crossed with the rules. When a rule has no articles at some distance, its cell is NULL (blank) instead of carrying the running total forward. `coalesce(c.n, 0)` only covers rows where rule is NULL. Latent on the full dump, but reachable on MAX_BATCHES subsets. Fix: build d as `(SELECT DISTINCT rule, ord FROM c) CROSS JOIN generate_series(0,35)`.
17. [CORRECTNESS] src/main.rs:127-131 (rust-3, downgraded). The chained `.replace` calls decode `&amp;quot;` and `&amp;#39;` twice. `&ndash;`, `&#x27;`, other numeric references and other named entities are not decoded at all. The `&amp;nbsp;` example was refuted: it gives the correct single-decode result. Rare in link targets. Fix: a single left-to-right decode pass.
18. [CORRECTNESS] src/main.rs:135-136 (rust-5). `split_whitespace().join("_")` does not collapse mixed or doubled `[ _]` runs, so `Foo _Bar` and `Foo__Bar` never match the canonical title `Foo_Bar`. Rare. Fix: map '_' to ' ' before splitting.
19. [CORRECTNESS] sql/03_report.sql:23-24 (general-purpose-3). Distance 30 gets its own row ('30'), and distances 31-39 are labelled '30-39' (philosophy.txt:366-367). No article is counted twice; the label is off by one. Fix: use `< 30`, or label the bucket from 31.
20. [CORRECTNESS] tools/psql_to_md.py:89-90 (python-4). `re.search(r"rule = (\w+)", line).group(1)` has no None guard, so any `####` line without "rule = <word>" crashes the converter. Latent: the only current source (06_summary_rule.sql:4) always matches.
21. [CORRECTNESS] [UNVERIFIED] tools/psql_to_md.py:34-42, 118, 131 (python-5). Escaping covers only backslash and pipe. Pandoc/Markdown metacharacters in Wikipedia titles (`*`, `` ` ``, `$`, `<`, `[`, a leading `#` or `-` on free-text lines) in the randomly sampled chains can become emphasis, math or raw HTML, or break the xelatex build. `_` is not a vector, because cell() maps it to a space. No instance appears in the current philosophy.md. The converter and pandoc repro was held.
22. [PERFORMANCE] [UNVERIFIED] sql/02_topology.sql:58-69 (performance-1, major). `strip_leaves` reruns a full-table `DELETE ... WHERE NOT EXISTS` every round, all inside one function call, so one transaction, and dead tuples are never reclaimed. That makes it O(rounds x N). Measured in run.log: skip_parens 17.1M rows, 189 rounds, 50.0 s; skip_italics 15.5M rows, 189 rounds, 46.3 s. The claim that it is the "single most expensive step" was refuted: pass 2c is slower for both rules (56.8 s and 69.1 s), so this is the second most expensive. Fix: a frontier-based strip (DELETE ... RETURNING next_id into a frontier table, and later rounds restricted to frontier ids). The predicted O(N) speedup and identical surviving set were not measured.
23. [PERFORMANCE] [UNVERIFIED] sql/02_topology.sql:16 (performance-2). `wiki_topology_<rule>` keeps its PRIMARY KEY during both recursive BFS INSERTs, which arrive in random id order: 25.5-69.1 s for 10-18M rows. `ALTER TABLE ADD PRIMARY KEY` after pass 2c keeps the visited-once assertion and builds the index sorted, at about 2 s per 19M rows. Pass 2a's anti-join would lose the index, so its cost has to be timed as well. The per-row rate is flat at about 2.5 us, which suggests the gain is modest. Unmeasured.
24. [PERFORMANCE] sql/01_load.sql:35-38 (performance-3). `DISTINCT ON (title) ... ORDER BY title, is_redirect, ctid` sorts all 19.3M rows at full width (title plus five target columns) to drop 17 duplicates. It takes 37.6 s, the largest statement in the load (COPY 14.7 s, index 8.0 s). A narrow hash aggregate on title followed by a ctid delete avoids the wide sort, but could spill without enough work_mem. The saving is unmeasured.
25. [PERFORMANCE] src/main.rs:433-449, 369-377 (performance-5). The scanner runs `stream_starts` over the whole 27 GB mapping (4.6 s) before sending the first batch, so all workers sit idle for about 2.9% of the 158.7 s parse. `memmem::find_iter` is already incremental, so batches could be sent as soon as STREAMS_PER_BATCH+1 starts are known. The saving is probably smaller with a cold page cache.
26. [PERFORMANCE] sql/04_compare.sql:10-15 and sql/06_summary.sql:12-17 (performance-4). Each stage materializes a 36.2M-row TEMP `by_rule` table (5 x 7,249,098 rows) with no ANALYZE. Autovacuum skips temp tables, so the self-joins at 04_compare.sql:44 and :57 are planned blind, and temp_buffers stays at its 8 MB default. The "gained/lost" and "clicks compared" queries could run as FILTER aggregates directly on wiki_articles, whose columns are already denormalized. The cost is unquantified because \timing is off in the docs stage.
27. [RESOURCES] src/main.rs:441-444, 456-457 (security-1). A single-stream or malformed dump yields starts=[0], which becomes one batch spanning the whole file. That leads to `Vec::with_capacity(len*8)`, about 190 GB, then an unbounded `read_to_end` of about 100 GB, with no format check. The Makefile:15 example (`DUMP=~/dumps/enwiki.xml.bz2`) makes the wrong-format mistake plausible. Operational risk only: the input is chosen by the operator, and there is no attacker or decompression-bomb path. Fix: reject the input when starts.len() is far below data.len()/~1 MB, and cap the preallocation. The same reviewer reported the rest of the security lens clean: mmap soundness, byte-index bounds in markup_skip_len and the namespaced-link skip, `%I`/regclass `%s` in dynamic SQL, the operator-set :rule/:csv/env vars, and the README scoping fsync=off to a rebuildable cluster.

### Coverage Gaps
- Verification could not run anything. All six round-1 verifications (rust-1, devops-2, devops-4, performance-1, performance-2, python-5) were inconclusive, because the environment held or banned `cargo test`, `make -n`, `psql` and the python3 converter run. Those findings are tagged UNVERIFIED. rust-1 and devops-2 are deterministic from the source. The impact and speedup figures for the others are unmeasured.
- Concurrency and throughput pipeline: the only finding is performance-5. Nobody reviewed the BTreeMap reorder-buffer correctness, worker panic or early channel-close behavior under panic=abort (possible hang or partial CSV), AtomicU64 orderings, or bounded-channel sizing.
- PostgreSQL graph-topology correctness: no findings and no clean report on cycle canonicalization (canonical id and length), the second BFS from cycle members, or which duplicate wins the DISTINCT ON tie-break (is_redirect, ctid). Redirect collapse is covered only through general-purpose-5.
- PostgreSQL planner/tuning: the enable_mergejoin/enable_hashjoin=off scoping around the recursive CTEs, missing ANALYZE between stages, and recursive working-set growth were not assessed beyond performance-1, -2 and -4.
- Makefile/bash Darwin/GNU portability (gsed vs sed, GNU make version features, pandoc/xelatex availability) was not reviewed.

### Disputes Resolved (low-stakes)
- devops-5 (.gitignore lacks .DS_Store and .claude/) vs cross-check (refuted): resolved in favor of the cross-check, and the finding is discarded. `git status --porcelain --ignored` shows `!! .DS_Store`, so the global excludesfile (~/.gitconfig core.excludesfile) already ignores it. The reviewer withdrew that half. The remaining point, that `.claude/` is untracked and not ignored, is accurate but is a repo-convention choice with no correctness impact, and the operator's workflow forbids `git add .`. Optional hygiene: add `.claude/reviews/` (and, for portability, `.DS_Store`) to the repo .gitignore.
### Held verification results

All four held groups were approved by the operator and run in foreground agents after the workflow returned. Four read-only lookups the verifiers had already worked around with other tools (sed/grep of the Makefile, SQL and run.log) were not rerun.

- **Finding 1 (rust-1, is_namespaced) — verified.** A temporary `#[cfg(test)]` module was appended to src/main.rs; `assert!(!is_namespaced("Dune: Part Two"))` failed with "Dune: Part Two treated as namespaced" (the remaining assertions did not run after the first panic). src/main.rs was restored; `git diff --stat src/main.rs` is empty. In wiki-phil, 24,390 in-dump titles match `^[A-Z][a-z-]{1,11}:_` (33,069 with the looser `^[A-Za-z-]{2,12}:`). Random examples: Pendragon:_The_Merchant_of_Death, Dominion:_Hinterlands, Aliens:_Harvest, Nudge:_Improving_Decisions_About_Health,_Wealth_and_Happiness, Kohan:_Battles_of_Ahriman. Every first link to one of these is currently skipped.
- **Finding 3 (devops-2, make docs walks back to the dump) — verified.** `make -n -W src/main.rs pdf` (the recipe docs delegates to) plans `cargo build --release`, the parser run on the dump, and `psql ... -f sql/01_load.sql`, then all five topology runs. `make -n DUMP=/nonexistent.bz2 docs` and `... stats` both fail before any recipe with `No rule to make target '/nonexistent.bz2', needed by 'wiki_edges.csv'`. `make -n docs` itself cannot show the effect because `-n` does not execute the parent's touch/rm. The make in use is Xcode's GNU make 3.81.
- **Finding 13 (devops-4, concurrent CREATE OR REPLACE FUNCTION) — verified.** Against a scratch database (created and dropped), 5 parallel loops × 200 calls: run 1 failed 368/1000 (364 × `tuple concurrently updated`, 4 × `duplicate key value violates unique constraint "pg_proc_proname_args_nsp_index"`); run 2 failed 365/1000. About 37% failure per call under 5-way contention. wiki-phil was not touched.
- **Finding 21 (python-5, Markdown metacharacters) — verified, latent.** Sample titles through tools/psql_to_md.py and the Makefile's pandoc/xelatex flags: `C*-algebra → *NSYNC` → `C\emph{-algebra → }NSYNC`; `Ke$ha → $1 coin$` → inline math `\(1 coin\)`; `<Foo> → <b>bar</b>` → `→ bar` (raw HTML dropped, title lost); `[link](x)` → `\href{x}{link}`; a bullet beginning `- dash` becomes a nested list; backticks become `\texttt`. The PDF built with exit 0 and no warnings, so the corruption is silent. The current philosophy.md contains none of these characters in titles.
- **Finding 22 (performance-1, strip_leaves O(rounds × N)) — verified, speedup modest.** On a rebuilt 17,126,202-row pre-strip set for skip_parens (matches run.log), current strip_leaves: 55.7 s and 62.5 s; frontier-based strip: 30.3 s, 35.2 s, 28.9 s, 189 rounds in both. Surviving sets identical: a EXCEPT b = 0, b EXCEPT a = 0, both equal cycle_nodes_skip_parens at 53,512 rows. Of the frontier time, round 1 is 14.9 s and round 2 is 5.4 s, so round 1 is the next cost to attack (build the id index after round 1). About 1.8×, not an order of magnitude.
- **Finding 23 (performance-2, PK maintained during BFS INSERT) — verified; the index-loss concern is falsified.** Pass-1 INSERT for parens_ok, 18,409,060 rows, 3 runs each: with PK 58.54 / 58.51 / 58.33 s; without PK 35.28 / 35.20 / 35.83 s plus ADD PRIMARY KEY 1.82 / 1.53 / 1.70 s, total ≈ 37 s (36% saving, spread under 2%). Pass 2a's `NOT EXISTS` anti-join runs as a Parallel Hash Anti Join with a Seq Scan on the topology table in 1.43 s with the PK and 1.42 s without; the index is never used.

All audit_* tables and functions were dropped; pg_class and pg_proc show none. No repo file was changed by verification.
